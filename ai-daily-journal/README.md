# AI日誌

CodexやClaude Codeとの1日を、単なる会話要約ではなく「何を考え、決め、作り、何が残ったか」まで読み返せるMarkdownへ変える。

## 30秒で開始

1. 利用中のAIを選ぶ
2. リンク先にある1つの枠をコピーする
3. 新しい作業へ貼り付ける

[Codex向けをコピー](prompts/codex.md) ｜ [Claude Code向けをコピー](prompts/claude-code.md)

貼り付け後は、AIが実際のPCを調査し、不明点だけを確認してから実装、テスト、修正、再テストまで進める。

## これは何か

完成済みアプリや全PC共通のインストーラーではなく、環境適応型の構築プロンプト。

OS、ログ形式、Obsidian、利用できる自動実行方法はPCごとに違う。そのため実装方法を一つに固定せず、次の合格条件を固定している。

- 実在するログとスキーマを確認してから読み取り方法を決める
- CodexとClaude Codeを別々に抽出してから1日分へ統合する
- AIの報告、実物で確認した事実、AIによる考察を混ぜない
- 日付単位の排他制御、一時生成、検証、原子的公開、公開後監査を行う
- 同じ日の完成済み日誌を上書きしない
- 毎朝7時の設定と、PC停止後の補完経路を実物で確認する
- 未取得、未対応、未検証を成功として補完しない

## 完成後に残るもの

- `YYYY-MM-DD_AI-Journal.md` 形式の日誌
- Obsidian Vault、または指定したローカルフォルダへの保存
- 毎朝7時に前日分を生成する自動実行
- 手動で対象日を指定できる実行入口
- 重複生成の防止、失敗時の補完、実行ログとエラーログ
- 取得元と処理結果を追跡できる検証記録

## 目指す流れ

```text
Codexの実ログ ── 個別抽出 ─┐
                            ├─ 秘密情報を除外したdigest ─ 意味を統合 ─ 検証 ─ Markdown公開
Claude Codeの実ログ ─ 個別抽出 ┘
```

単語を拾って並べただけの文章は完成扱いにしない。日次実行で意味の統合を担うAIを安全に呼べない場合は、その範囲を未完成として報告する。

## 日誌の最低構成

- 今日の主要イベント
- 考えたこと・気づき
- 決定したこと
- 作ったもの・進めたこと
- 変更・修正したこと
- 未解決・保留
- 次にやること
- AI別作業履歴
- 元資料

[架空データの出力例](examples/2026-08-01_AI-Journal.md)で完成イメージを確認できる。

## 使う前の確認

- プロンプトはローカル環境へファイルや自動実行設定を追加する
- AIは変更前に、取得元、保存先、実行方式、外部送信の有無を報告する
- APIキー、トークン、個人情報、顧客情報を日誌へ入れない
- 元ログは読み取り専用で扱う
- ログ本文を新しい外部サービスへ送る必要がある場合は、実行前に確認を求める
- 実行用フォルダと日誌保存先には、大文字小文字だけが違う名前を使わない

## 完成の判定

構築を担当したAIの自己申告ではなく、プロンプト内の受け入れ試験表で判定する。

最低でも、実ログ取得、複数ファイル探索、AI別抽出、意味の統合、秘密情報除外、同日再実行、同時実行、途中失敗、原子的公開、公開後監査、自動実行の登録内容と同じ入口の手動起動を確認する。

確認できない項目が一つでもあれば、`未確認`または`未対応`として残し、完成と表現しない。

詳しい検証条件と現在の確認範囲は [VERIFICATION.md](VERIFICATION.md) を参照。

## 実運用との関係

作者のローカル環境では、AI別抽出、日付単位の排他制御、一時保存、digest固定、原子的公開、公開後監査を含む仕組みが稼働している。

公開版は、その実装コードや個人環境を配るものではない。環境固有の処理と、環境をまたいで守る合格条件を分け、ほかのPCで同じ目的へ近づけるためのプロンプトを配布している。
