# AI日誌

CodexやClaude Codeとの1日を、単なる会話要約ではなく「何を考え、決め、作り、次に何を残したか」まで読めるMarkdownへ変える。

## 30秒で開始

1. 利用中のAIを選ぶ
2. リンク先にある1つのコード枠をコピーする
3. 新しいCodexまたはClaude Codeの作業へ貼り付ける

[Codex向けをコピー](prompts/codex.md) ｜ [Claude Code向けをコピー](prompts/claude-code.md)

貼り付け後は、AIがPCを調査し、不明点だけを確認してから実装、テスト、修正、再テストまで進める。

## 完成後に残るもの

- Codex、Claude Codeなど、取得可能なログの個別抽出
- AIをまたいだ重複の除去と1日単位の統合
- `YYYY-MM-DD_AI-Journal.md` 形式の日誌
- Obsidian Vault、または指定したローカルフォルダへの保存
- 毎朝7時に前日分を生成する自動実行
- 重複生成の防止、失敗時の次回補完、実行ログとエラーログ
- 実ログを使ったテスト日誌1件と、変更内容の完了報告

利用できるログ、保存先、自動実行の方法はPCごとに異なる。見つからないログや実現できない自動化を、AIが実装済みとして扱わないこともプロンプトへ含めている。

## 仕組み

```text
Codexのログ ─┐
              ├─ AIごとに抽出 ─ 重複を除去 ─ 1日へ統合 ─ Markdown保存
Claude Code ─┘
```

毎朝の自動実行では、PCのローカルタイムゾーンを基準に前日分を1件だけ作る。同じ日付の完成済み日誌があれば上書きせず、処理を止める。

## 使う前の確認

- プロンプトはローカル環境へファイルや自動実行設定を追加する
- 変更対象と保存先は、実装前にAIの調査結果で確認する
- APIキー、トークン、個人情報、顧客情報を日誌へ入れない
- ログを外部サービスへ送る必要がある場合、AIは事前に確認する
- PC停止中の補完方法は、OSと利用できるスケジューラに合わせて決める

## 実運用との関係

作者のローカル環境では、CodexとClaude Codeのログを別々に抽出し、日付単位の重複防止、生成途中の一時保存、完成時の原子的な公開、公開後の監査を行う実装が稼働している。

この公開版は、その設計をほかの環境へ移植するためのプロンプト。本人用の実装コード、実ログ、個人パスは公開していない。また、この配布プロンプトを第三者のPCで実行した結果はまだ確認していない。

## 成功の判定

構築を担当するAIの報告だけで終わらせず、次の6点を実物で確認する。

1. 対象日のログを取得できる
2. AIごとの出来事を抽出できる
3. 重複を除いて1日分へ統合できる
4. 必須見出しを持つMarkdownを生成できる
5. 指定先へ既存ファイルを上書きせず保存できる
6. 毎朝7時の自動実行と失敗時の補完を確認できる

どれかを確認できない場合は、未確認のまま完了扱いにしない。
